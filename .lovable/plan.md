
# Прогресс‑скролл для вылупления + расширенные подсказки

## 1. Триггер стадий по прогрессу скролла (а не px)

Сейчас стадии (`wobble` → `crack-1` → `crack-2` → `peek` → `hatched`) переключаются на фиксированных значениях `window.scrollY` (80/250/500/800/1100 px). На мобилке страницы длиннее, и пользователю приходится скроллить «вечно», чтобы птенец вылупился; на коротких экранах наоборот — мгновенно.

Переходим на единую безразмерную метрику **0…1**, одинаковую для любого устройства:

```
progress = scrollY / (documentHeight - viewportHeight)
```

Если страница не скроллится (`documentHeight ≤ viewportHeight`) — `progress = 1` (вылупляется сразу, на коротких страницах сразу получаем компаньона).

**Маппинг прогресса → стадия:**

| progress | стадия |
|---|---|
| 0.00 | `egg` |
| ≥ 0.05 | `wobble` |
| ≥ 0.20 | `crack-1` |
| ≥ 0.40 | `crack-2` |
| ≥ 0.65 | `peek` |
| ≥ 0.90 | `hatched` |

Также: если пользователь проскроллил **до футера** (видимый последний экран) — гарантированно `hatched`, даже если арифметика дала чуть меньше из-за резайза.

**Реализация в `MascotProvider.tsx`:**
- Заменить вычисление `next` в `onScroll` на `progress`-маппинг.
- Слушать `resize` и `orientationchange`, чтобы пересчитывать стадию (на мобилке высота viewport меняется при появлении адресной строки).
- Считать высоту документа надёжно: `Math.max(document.documentElement.scrollHeight, document.body.scrollHeight)`.
- Сохранить правило «стадия не откатывается назад».
- Сохранить ранний выход для `prefers-reduced-motion` и для уже сохранённого в `sessionStorage` состояния `hatched`.

**Что меняется в `pickTip()`:**
- Не повторять последнюю подсказку **в рамках текущего роута** (сейчас глобально).

## 3. Acceptance criteria

- На любой странице (короткой или длинной), на десктопе и на мобилке, птенец проходит все стадии вылупления при прокрутке от верха до низа примерно одинаково — к ~90% прокрутки уже вылупился.
- На странице, которая помещается в один экран (нет скролла), сразу появляется вылупившийся птенец.
- При смене размера окна / повороте телефона стадия пересчитывается без сбоев.
- На приоритетных роутах (`/opt/`, `/catalog/`, `/faq/`, `/kontakty/`, и т.д.) птенец не повторяет одну и ту же фразу подряд — есть как минимум 3 разных варианта.
- На большинстве страниц как минимум одна из подсказок несёт CTA с переходом в WhatsApp.
- Состояние `hatched` всё так же сохраняется в sessionStorage и не «откатывается» при переходе на новую страницу.
