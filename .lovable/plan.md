## Что улучшаем

Существующие страницы уже есть, но требуют усиления: на `/opt/` форма не собирает данные об объёме/частоте и не отправляет лид в WhatsApp; категорийные страницы короткие и без блока «фасовки/упаковки».

## 1. Страница `/opt/` — форма «Получить прайс»

Расширяем `LeadForm` (или создаём специализированный `OptLeadForm`), чтобы:
- Поля: имя, телефон, организация (опц.), категория продукта (select: яйца / мясо / инкубационное / всё), **примерный объём в неделю** (select: до 500 / 500–2000 / 2000–10 000 / более 10 000 шт.), **частота поставок** (select: разово / еженедельно / 2 раза в неделю / по графику), комментарий.
- Валидация zod, ограничение длин, trim.
- Submit: формирует структурированный текст заявки и **открывает WhatsApp** с этим текстом (`window.open(whatsappUrl(text))`), параллельно пишет лид в console.log (stub) и показывает success-state с двумя кнопками — «Написать в WhatsApp ещё раз» и «Позвонить».
- Дополнительно над формой — крупные CTA: «WhatsApp» и «Позвонить» (мгновенный канал для тех, кому форма не нужна).

Контент-блоки на странице:
- Сегменты клиентов (HoReCa, магазины, лавки, столовые) — карточки.
- Что входит в опт-пакет (документы, график, упаковка) — уже есть, чуть расширим.
- Кейсы/типовые объёмы (без выдуманных брендов — обобщённые: «кофейня», «ресторан», «магазин у дома»).
- FAQ для опта (мин/максзаказ, отсрочка, документы, доставка, договор) + JSON-LD FAQPage.

## 2. Категории — `/perepelinye-yaytsa/`, `/inkubatsionnoe-yaytso/`, `/molodnyak/`

Для каждой добавляем единый набор блоков (на базе нового компонента `CategoryPageLayout`):

1. **Hero** (уже есть) + бейджи доверия (свежесть, документы, своя ферма).
2. **Описание + «для кого»** (уже есть, чуть расширим).
3. **Фасовки / варианты** — 2–4 карточки с фото-плейсхолдером, описанием, ценой «от …» / «по запросу», кнопкой «Заказать в WhatsApp» (текст заранее сформирован под конкретный SKU). Для `molodnyak` цены — «по запросу».
4. **Условия хранения и транспортировки** (уже есть, оформим списком с иконками).
5. **Как заказать** (3 шага: WhatsApp → согласование → доставка/самовывоз).
6. **FAQ** — расширим до 5–6 вопросов на странице, JSON-LD `FAQPage`.
7. **Финальный CTA-блок** — крупный «Заказать в WhatsApp» + телефон.

Цены остаются ориентировочными ("от … ₽") согласно ТЗ; для `molodnyak` — "по запросу".

JSON-LD `Product`+`Offer` — добавляем только для тех фасовок, где указана конкретная цена (т.е. в яйцах и инкубационном). Для «по запросу» — не добавляем (требование ТЗ).

## 4. Acceptance

- На `/opt/` форма принимает объём + частоту, по сабмиту открывается WhatsApp с готовым текстом, console.log пишет лид; на странице доступны прямые WhatsApp/tel.
- Каждая из 3 категорий имеет: hero, фасовки с CTA на WhatsApp (текст с конкретным SKU), HowToOrder, ≥5 FAQ, финальный CTA.
- JSON-LD `Product+Offer` валиден на яйцах и инкубационном; в `molodnyak` — только `FAQPage`.
- Никаких `:slug`, `brand.example`, `[object Object]`, "Ниша:"; canonical/title/description остаются корректными.
