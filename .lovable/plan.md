
# Reduced-motion и плавная синхронизация стадий между страницами

## 1. Полная поддержка `prefers-reduced-motion`

Сейчас при reduced-motion стадия сразу ставится в `hatched`, но:
- Speech bubble всё равно делает spring scale-in.
- Скорлупки (`ShellPieces`) анимируются framer-motion (падают с пружиной).
- Walk/blink/chirp — уже отключены.

**Что меняем:**
- В `MascotProvider`: при `reducedMotion=true` НЕ писать в `sessionStorage` маркер «вылупился» (чтобы при выключении флага у пользователя анимация всё ещё могла отыграть в обычном режиме). Просто рендерим финальное состояние локально.
- В `Mascot.tsx`:
  - При `reducedMotion` не рендерить `ShellPiecesOnce` вообще (никаких падающих скорлупок).
  - В `Chick`: убрать `bob`/`shadowScale`/`leg rotation` (передавать `walkPhase=0`), `blink=false` всегда.
  - `headRot=0` всегда (отключить eye-tracking RAF).
- В `SpeechBubble`:
  - Если reduced-motion → `transition={{ duration: 0 }}` и без scale (initial=animate). Текст показывать сразу целиком (typewriter уже отключён по `prefers-reduced-motion` локально, переключим на проп от провайдера для консистентности).
- Подсказки и их CTA продолжают появляться: route-change tip и idle-таймер (18-28 сек) уже работают независимо от reduced-motion. Сохраняем как есть.

Acceptance: при системной настройке «уменьшить анимацию» — в шапке статичный птенец (без ходьбы/морганий/скорлупок), облако возникает мгновенно с готовым текстом и кнопкой CTA, при смене роута — новая подсказка без анимации.

## 2. Синхронизация прогресса при переходе между страницами

Сейчас `useEffect` зависит от `[stage, location.pathname]` и пересчитывает стадию при смене роута. Но есть проблемы:

a) **Контент новой страницы появляется асинхронно** (картинки, ленивые секции). На момент первого `compute()` `documentHeight` ещё маленький — `progress` может оказаться 1 на короткое окно и неоправданно перевести в `hatched`. Нужен `ResizeObserver` на `document.body` + дебаунс.

b) **Резкие скачки стадии**. Если новая страница длинная и пользователь сразу проскроллил — может перепрыгнуть с `wobble` сразу в `peek`, минуя промежуточные. Нужно ограничивать переход максимум на одну стадию вперёд за тик при обычной прокрутке (но сохранить «дотянуть до hatched» когда у футера).

c) **Перезагрузка страницы** не сохраняет промежуточные стадии — пользователь начинает каждый раз с яйца, даже если уже видел трещины. Сохраняем не только `hatched`, а текущую стадию в `sessionStorage` (`sp_mascot_stage`). При инициализации читаем её и стартуем с неё (не регрессируем).

d) **Короткая страница после длинной**. Сейчас при переходе на короткую страницу `progress=1` → мгновенный `hatched`. Это OK, но для плавности: если предыдущая стадия была, например, `wobble`, скачок к `hatched` без анимации трещин выглядит резко. На коротких страницах добавляем небольшую задержку (300-500мс) перед последовательным «доигрыванием» промежуточных стадий: `wobble → crack-1 → crack-2 → peek → hatched` с интервалом ~250мс. Маскот «дозревает» в шапке, не дёргает пользователя.

**Реализация в `MascotProvider.tsx`:**

- Новое состояние / refs: `prevPathname`, `pendingShortPageTimer`.
- При смене `location.pathname`:
  1. Сброс tip (`hideTip`).
  2. Запускаем `compute()` спустя 1 RAF (чтобы новый layout успел отрендериться).
  3. Подключаем `ResizeObserver(document.body)` для пересчёта при подгрузке контента (отключаем при unmount/смене роута).
- В `compute()`:
  - Если `scrollable <= 4` (нет скролла) и текущая стадия НЕ `hatched`: запускаем «доигрывание» — таймером последовательно проставляем стадии вверх до `hatched`, шаг 250мс. Если новая стадия пришла из реального скролла — таймер отменяется.
  - Иначе: ограничиваем шаг — `next = min(target, prev + 1)` по `STAGE_ORDER`. Это гарантирует прохождение всех промежуточных стадий, даже при резком скролле.
  - Bottom guard оставляем (доскролл до футера всё равно даёт `hatched`).
- Сохранение в sessionStorage: при каждом изменении `stage` пишем `sp_mascot_stage`. При маунте — читаем, стартуем с этой стадии (или `hatched`, если она там).

**Acceptance:**
- Переход с главной (длинной) на короткую `/kontakty/`: без рывка, маскот плавно «доигрывает» оставшиеся стадии в шапке за ~1 сек, не телепортируется.
- Переход на длинную страницу: стадия не регрессирует и не перепрыгивает через ступеньки — даже резкий скролл вниз проходит все промежуточные за пару кадров.
- Перезагрузка страницы: маскот стартует с последней зафиксированной стадии.
- Отложенная подгрузка контента (картинки) не вызывает «прыжков» стадии.
