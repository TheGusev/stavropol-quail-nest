## Задача

Сейчас в каталоге пять плоских пунктов: «Перепелиные яйца», «Инкубационное яйцо», «Мясо перепела», «Молодняк», «Клетки». Нужна нормальная иерархия категорий (группа → подкатегории) и страницы под все типы товаров из брифа.

## Что строим

### 1. Хаб-страницы групп (4 шт.)
`/yaytsa`, `/ptitsa`, `/myaso`, `/soputstvuyushchie` — лендинги вида «Каталог», но только с карточками подкатегорий своей группы. Каждая использует `PageHero` + сетку `CategoryCard` + короткий FAQ + `FinalCta`. SEO `head()` со своими title/description, `BreadcrumbList` JSON-LD.

### 2. Карточки подкатегорий (новые страницы)
Все новые страницы строятся по одному шаблону существующих (`molodnyak.tsx`, `inkubatsionnoe-yaytso.tsx`):
- `PageHero` с фото и кратким описанием из брифа.
- Блок «Что это / для кого подойдёт» (`Prose`) — текст из брифа.
- Блок «Фасовки и цены» — `PackagingCard` с вариантами (например, помёт: свежий / компост / гранулы; выбракованные перепела: живой вес / охлаждённые тушки / замороженные тушки).
- `HowToOrder`, `FaqAccordion` (3–5 вопросов), `FinalCta`.
- `head()` с уникальным title/description, `Product` и `FAQPage` JSON-LD.
- Картинка-заглушка через imagegen в `src/assets/cat-*.jpg` (одна на подкатегорию).

### 3. Расширение `CategoryCard`
В `src/components/CategoryCard.tsx` тип пропа `to` расширяется до union всех новых маршрутов (TanStack требует литералы). Альтернативно — снять литеральное ограничение и брать `to` как `string` через `as never` каст в Link, но лучше явный union для type-safety.

### 4. Навигация
- **Header (`src/components/Header.tsx`)**: вместо плоского пункта «Каталог + Клетки» — десктопное меню с ховер-дропдауном «Каталог» (4 группы → подкатегории) и пунктами «Клетки», «Опт», «Доставка», «О ферме», «FAQ», «Контакты». В мобильном drawer — раскрывающиеся секции по группам (accordion).
- **Footer (`src/components/Footer.tsx`)**: колонка «Каталог» получает заголовки групп со ссылками на хабы и под ними — подкатегории.
- **`/catalog`**: остаётся как обзор всех 4 групп + клеток (4–5 крупных карточек, ведут на хабы, не на товары).
- **`/` (index.tsx)**: блок «Наша продукция» — 4 карточки групп + «Клетки» (5 карточек, ведут на хабы).

### 5. SEO-инфраструктура
- `public/sitemap.xml` — добавить все новые URL.
- `public/llms.txt` — обновить раздел «Категории продукции» по новой структуре.
- В каждую новую страницу — `BreadcrumbList` JSON-LD (Главная → Группа → Подкатегория).

### 6. Маскот-подсказки
В `src/lib/mascot-tips.ts` — короткие реплики для новых хаб-страниц и нескольких ключевых подкатегорий (помёт, родительское стадо, маринованные).

## Что НЕ меняем
- Поведение хедера (бургер, маскот), `PageHero` (без карточки), скорость маскота, мобильный маскот — не трогаем.
- Существующие страницы `perepelinye-yaytsa`, `inkubatsionnoe-yaytso`, `myaso-perepela`, `molodnyak`, `kletki` остаются на своих URL — только добавляем хлебные крошки и обновляем перелинковку.

## Технические детали

- Маршруты — flat-точечная нотация TanStack: `ptitsa.sutochnye.tsx`, `myaso.zamorozhennoe.tsx`, `soputstvuyushchie.pomet.tsx` и т.д. Файл-родитель `ptitsa.tsx` рендерит `<Outlet />` только если нужны общие layout-элементы; иначе `ptitsa.tsx` — обычная hub-страница, дочерние пути работают независимо (имена с точкой не требуют `<Outlet />`).
- Все новые routes — клиентские страницы без серверных функций.
- Контент-копирайтинг — на основе текста из брифа пользователя, переписать естественным языком (без копипаста маркеров).
- Картинки генерируем фоторепортажным стилем фермы под Ставрополем.
